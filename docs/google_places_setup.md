# Google Places setup

Flutter Web sends Google Places, autocomplete, place details, and geocoding
requests to the `google-places` Supabase Edge Function. The browser never
receives the server Google key. Place photos and static-map fallbacks use
HMAC-signed proxy URLs generated by the function.

## Supabase

Create a random signing secret (at least 32 random bytes), then configure and
deploy the function:

```sh
supabase secrets set GOOGLE_MAPS_API_KEY="server-key" GOOGLE_MAPS_PROXY_SIGNING_SECRET="random-64-character-secret"
supabase functions deploy google-places --no-verify-jwt
```

`verify_jwt` is disabled at the gateway because signed image GET requests
cannot attach an Authorization header. The function validates the current
Supabase user itself for every POST request; unauthenticated GET requests must
carry a valid HMAC signature.

Restrict the server key to **Places API**, **Geocoding API**, and **Maps Static
API**. If the Supabase project has stable egress IP addresses, also apply an IP
application restriction. Never apply an HTTP-referrer restriction to this
server key.

## Native Android and iOS

Native Places REST behavior is unchanged. Pass its key only to native builds:

```sh
flutter run --dart-define=GOOGLE_MAPS_API_KEY="native-key"
```

For the Android Maps SDK, add this uncommitted line to
`android/local.properties`:

```properties
GOOGLE_MAPS_API_KEY=native-maps-sdk-key
```

For the iOS Maps SDK, create the ignored file `ios/Flutter/Secrets.xcconfig`:

```text
GOOGLE_MAPS_API_KEY=native-maps-sdk-key
```

Use separate Android/iOS SDK keys where practical. Restrict Android keys by
package name and SHA certificate and to **Maps SDK for Android**; restrict iOS
keys by bundle identifier and to **Maps SDK for iOS**. Keep the native Places
REST key API-restricted to only the Places/Geocoding/Static APIs the build uses.

## Web Maps JavaScript SDK

Interactive `GoogleMap` widgets require a separate browser key. The deployment
script writes `build/web/google_maps_config.js` from
`GOOGLE_MAPS_BROWSER_API_KEY`. This key is public by design: restrict it by the
production/local HTTP referrers and enable only **Maps JavaScript API**. Never
reuse the server Places key.

The web build command is:

```sh
GOOGLE_MAPS_BROWSER_API_KEY="restricted-browser-key" ./build.sh
```

For local `flutter run -d chrome`, copy the committed example and set the same
kind of browser-only key:

```sh
cp web/google_maps_config.example.js web/google_maps_config.js
flutter run -d chrome
```

`web/google_maps_config.js` is gitignored. It must contain
`window.tourisTrikeConfig.googleMapsBrowserApiKey`; never place the server-side
`GOOGLE_MAPS_API_KEY` there.

Do not add `.env` to Flutter assets. For non-web local values such as Gemini,
use `--dart-define` or `--dart-define-from-file` only on the intended target.
